# Seller Control — стартовый проект, НЕ готовая интеграционная система

Реальный Next.js + PostgreSQL проект с владельцем, защищёнными сессиями, товарами, историей себестоимости, планами, ручными расходами, журналом и адаптивными разделами. **Это первая работающая основа, а не финальное исполнение всех 16 разделов ТЗ**. Внешние API ещё не подключены и не проверены; ежедневное задание пока фиксирует пропуск, а не загружает данные. Интерфейс не генерирует вымышленные продажи.

## Быстрый запуск
1. Установите Node.js 22+ и PostgreSQL (либо создайте PostgreSQL в Railway).
2. `npm install`
3. Создайте `.env` по примеру `.env.example` и заполните `DATABASE_URL`, `SESSION_SECRET` (длинная случайная строка от 32 символов).
4. `npm run db:init`
5. `npm run dev`, затем откройте http://localhost:3000.
6. Зарегистрируйте первого владельца. Повторная регистрация владельца заблокирована.

## Проверки
`npm test`, `npm run typecheck`, `npm run build`.

## Публикация Railway
1. Загрузите папку проекта в **новый приватный репозиторий GitHub**. Не загружайте `.env`.
2. Railway → New Project → Deploy from GitHub; подключите репозиторий.
3. В проекте Railway добавьте PostgreSQL; скопируйте ссылку соединения `DATABASE_URL` в переменные веб-сервиса.
4. В Variables веб-сервиса укажите отдельный `SESSION_SECRET` (минимум 32 случайных символа).
5. Один раз запустите `npm run db:init` с доступом к той же БД.
6. В Railway опубликуйте веб-сервис с портом из `PORT` (Next автоматически его использует через npm start), включите HTTPS домен.
7. Отдельный Cron Service может использовать этот же код с командой `npm run sync` и расписанием `0 3 * * *` (UTC). Пока задание только журналирует `skipped`: настоящего обновления **нет**.
8. Включите резервное копирование PostgreSQL средствами Railway/провайдера; проверяйте восстановление на отдельной тестовой БД. До обновлений сохраняйте дамп и отслеживайте миграции.

## Реализовано / не реализовано

**Есть:** адаптивная навигация, все 7 разделов с честными пустыми состояниями, фильтры (площадка, период, товар), поиск/CSV операций, товары и история себестоимости, планы, ручные расходы, шифрование сохранённых ключей (AES-256-GCM), единственный владелец, сессии (httpOnly), защита действий от cross-origin, журнал попыток синхронизации, тесты базовых формул.

**Нет:** рабочие HTTP-коннекторы WB/Ozon, реальные заказы и продажи, импорт CSV, возвраты себестоимости и полные финансовые сверки, отправка уведомлений, сквозной OAuth, надёжная серверная финансовая агрегация, автоматическое обновление реальных данных, управляемые миграции, полное покрытие тестами, подтверждённые лимиты API. Реальная синхронизация НЕ должна включаться до проверки документации и реальных кабинетов.

Не используйте прототип для финансовых решений без сверки с первичными отчётами.
